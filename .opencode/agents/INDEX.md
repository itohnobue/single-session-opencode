# Agent Directory (8 agents)

Quick selection reference. All workflow instructions live in `AGENTS.md` — the Agent Delegation section (executor tiers T1/T2/T3, task splitting by volume, second-opinion rules, optional VERIFY block). Read it before delegating.

| File | Agent | Role |
|------|-------|------|
| prepare-agent.md | Prepare agent | Research generation when fresh web research is needed. FOCUS parameter = specialist identity; ≤3 queries per tech; full research report (no size cap) + compact digest (~10KB soft max) that the executor's prompt carries; quality self-review before delivery; task-context anchoring + provisional traps. |
| executor.md | Executor agent | The default executor for all tiers and work types (implementation, review, research, second-opinion s2). HIGH reasoning effort. T1 (plain — task context is the briefing, no research) or T2/T3 (after prepare: template → RESEARCH DATA → task); second-opinion runs (s2) with complementary-FOCUS research briefings. Post-fix review is NOT its job — that is postfix-reviewer's. |
| postfix-reviewer.md | Postfix reviewer | Post-fix review ONLY (always MAX reasoning effort): verifies applied fixes against their design (correctness, minimality, new bugs, test breakage, race conditions; verdict APPROVED / NEEDS-FIX). Strictly read-only — never used for any other task. |
| verification-analyst.md | Verification analyst | Extraction + synthesis for findings-heavy flows (merged s2 outputs, multi-report audits, VERIFY blocks): dedups/tags findings (both-found/single-found, PRIOR_FIX_ATTEMPT), routes investigated-and-rejected items into adversarial batches, compiles the synthesis grid (severity challenges, mechanism categories, FIX determination). Knowledge harvesting is NOT its job — the main model performs all harvesting in-session (AGENTS.md Memory System + T3 final stage). |
| adversarial-reviewer.md | Adversarial reviewer | Falsification gate — optional VERIFY block. The single distinct quality gate, ALWAYS at MAX reasoning effort (no lower-effort tier); batch sizes CRITICAL (1:1), HIGH (1:3), MEDIUM (1:10) are volume controls. Falsifies findings (FP → REJECTED, overstated → WEAKENED), challenges rejected-non-bug lists, prioritizes unique findings on merged s2 outputs; CONFIRMED findings drive fix + re-verify (convergence rule — loop continues while CONFIRMED HIGH+ remain). |
| web-searcher.md | Web researcher | Deep-research fallback for the main model when a task needs beyond the prepare budget. Internet research (standards, formats, versions, ecosystems, advisories). |
| research-analyst.md | Research analyst | Structured multi-source research — analysis/synthesis of gathered material (tech comparisons, literature reviews, market research). Source evaluation, confidence tiers, counter-evidence discipline. |
| data-researcher.md | Data researcher | Dataset research — data discovery, collection, quality assessment, pattern mining. Data-quality and source-quality gates, graduated confidence. |

The one general principle — the context rule (see AGENTS.md): plain is used ONLY when the task file already carries rich context (facts stated in PRIOR CONTEXT or already researched in); when the task file is thin and the task depends on facts it does not carry, research is injected to supply what the context lacks. Research data (digest + full report) is the briefing input of T2/T3 runs. Tiers: **T1 plain** (task context is the briefing — no research; use when research is not needed); **T2 researched** (prepare agent produces the research — thin context, external facts missing from the file, or precision/breadth matters); **T3 the full workflow** (any complex issue — findings → fixed & verified: review agents gather all info first, then research-backed s2, adversarial verification, fixes; T1/T2 end at EXECUTE). Always merge primary + s2.

Specialist identity = research data: the same task prepared with different FOCUS angles produces different specialists (see AGENTS.md Second-opinion rules).
